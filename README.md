# Reticker

Генератор синтетических минутных тикеров по торговым свечам Bybit для бэктестов.
CatBoost описывает условное распределение недостающих полей, а общий блочный
bootstrap остатков добавляет случайность с зависимостями во времени, между
полями, рынками и символами.

Поддерживаются **spot и linear USDT perpetual**. Символы задаются аргументами;
новый символ требует свечей, тикеров и переобучения. Вывод — один тикер на
закрытие каждой минуты. Funding, OI и внутриминутная траектория в v1 не входят.

## Установка

Python 3.12+, CPU. Зависимости закреплены в `uv.lock`.

```bash
uv sync --group dev
uv run reticker --help
```

Без `uv run` можно использовать `.venv/bin/reticker` и `.venv/bin/python`.

## Источник данных

Подключение задаётся через переменную окружения `CH_URL` или `.env` в текущем
каталоге. Переменная окружения имеет приоритет. Поддерживается native DSN:

```dotenv
CH_URL=clickhouse://USER:PASSWORD@HOST:9000/DATABASE
```

Допустима запись без `clickhouse://`; для TLS используется `clickhouses://`.
Специальные символы учётных данных должны быть URL-encoded. DSN не сохраняется
в артефактах. Все запросы к ClickHouse выполняются с `readonly=2`.

Ожидаются таблицы существующего сборщика:

- `kline`: `time`, `category`, `symbol`, `interval`, OHLC, `volume`, `turnover`;
- `spot_ticker`: `time`, `symbol`, `bid1_price`, `ask1_price`, `bid1_size`, `ask1_size`, `last_price`;
- `future_ticker`: те же поля, `category`, `mark_price`, `index_price`.

Свечи имеют `interval='1'`, а их `time` обозначает **начало** минуты. Строки
тикеров должны быть полными состояниями с биржевым временем. Чтение через
Unix timestamp сохраняет правильное время при разных часовых поясах таблиц.
Читается итоговое состояние `ReplacingMergeTree` через `FINAL`.

## CLI: полный конвейер

Все даты ниже — UTC, конец диапазона исключён. Символы в примерах можно заменить.
Каталоги вывода должны отсутствовать или быть пустыми.

```bash
uv run reticker inspect --symbols BTCUSDT ETHUSDT --markets spot linear

uv run reticker prepare \
  --symbols BTCUSDT ETHUSDT --markets spot linear \
  --start 2026-11-07T18:22:00Z --end 2026-11-09T11:52:00Z \
  --out artifacts/dataset

uv run reticker train \
  --dataset artifacts/dataset --out artifacts/model --threads 4

uv run reticker evaluate \
  --dataset artifacts/dataset --model artifacts/model --out artifacts/evaluation

uv run reticker generate \
  --model artifacts/model --symbols BTCUSDT ETHUSDT \
  --start 2026-11-08T00:00:00Z --end 2026-11-09T00:00:00Z \
  --seed 42 --out artifacts/generated
```

`prepare` требует свечей **каждого** выбранного рынка. Фьючерсные свечи загружает
внешний сборщик; reticker не подменяет их спотовыми. Если в базе пока только
спотовые свечи, используйте `--markets spot` при подготовке отдельного артефакта.

Назначение команд:

| Команда | Результат |
|---|---|
| `inspect` | Периоды и количество строк, список отсутствующих свечных потоков |
| `prepare` | Зафиксированная общая выборка `panel.parquet`, качество данных и временные разбиения |
| `train` | CatBoost-модели, банк остатков, метаданные, параметры и контрольные суммы |
| `evaluate` | `report.md`, полный `report.json` и `diagnostics.png`; по умолчанию 20 seed |
| `generate` | Parquet по `market=.../date=...`, манифест запуска и диагностика каждой порции |

Артефакт фиксирует набор рынков. Для генерации можно выбирать любой обученный
поднабор символов; для другого набора рынков нужно обучить отдельный артефакт.
Параметр `generate --markets`, если передан, проверяется на соответствие артефакту.

Многолетняя генерация идёт порциями (`--chunk-days`, по умолчанию 1).
Окна признаков, RNG и текущий блок сохраняются между порциями: одинаковые
входы, артефакт и seed дают одинаковые значения при разном размере порций.
Это не обещает одинаковую реализацию при изменении набора символов.

## Метаданные и исторические шаги

При подготовке текущие шаги берутся из публичного API Bybit и замораживаются
в артефакте. Для офлайн-работы и исторических правил используйте
`prepare --metadata instruments.json`:

```json
{
  "spot:BTCUSDT": [
    {"tick_size": "0.1", "quantity_step": "0.000001", "source": "provided"},
    {
      "valid_from": "2021-01-01T00:00:00Z",
      "valid_to": "2023-01-01T00:00:00Z",
      "tick_size": "0.01",
      "quantity_step": "0.000001",
      "source": "historical_override"
    }
  ]
}
```

Это пример формата, а не историческая спецификация BTC. Периоды полуоткрытые,
исторические правила не могут пересекаться. Правило без дат — fallback;
датированное правило имеет приоритет. Если fallback задан для каждого выбранного
инструмента, API не вызывается. Иначе недостающие fallback загружаются из Bybit.
Метаданные должны покрывать также предысторию признаков.

Текущий шаг не считается исторически достоверным: отчёт показывает число строк,
для которых использован fallback Bybit. Применяются `tickSize`, спотовый
`basePrecision` и контрактный `qtyStep`; минимальный размер ордера не является
минимальным размером котировки в стакане.

## Python API

```python
import pandas as pd
from reticker import (
    ClickHouseSource, Selection, PreparationConfig, TrainingConfig,
    GenerationConfig, prepare, train, evaluate, generate,
)

source = ClickHouseSource.from_env()
selection = Selection(("BTCUSDT", "ETHUSDT"), ("spot", "linear"))
dataset = prepare(
    source,
    PreparationConfig(selection, "2026-11-07T18:22Z", "2026-11-09T11:52Z"),
    "artifacts/dataset",
)
model = train(dataset, "artifacts/model", TrainingConfig(threads=4))
report = evaluate(dataset, model, "artifacts/evaluation")

for frame in generate(
    source, model,
    GenerationConfig("2026-11-08", "2026-11-09", seed=42),
):
    # frame — pandas.DataFrame; порция обычно содержит один день всех символов.
    print(frame.head())
```

Для работы без сервера есть `FrameSource(candles, tickers)` и
`MetadataCatalog({...})`; последний можно передать четвёртым аргументом `prepare`.
В DataFrame времени нужны UTC datetime, имена столбцов совпадают с источником.
Сохранённые объекты загружаются через `PreparedDataset.load(path)` и
`ModelBundle.load(path)` с проверкой контрольных сумм. Для потокового сохранения
служит `write_generation(source, model, config, output_dir)`.

## Данные и выходные поля

Временная метка результата — закрытие свечи. `last_price` равен её close.
Суточные high/low/volume/turnover вычисляются по последним 1440 минутам;
`prev_price24h` — close ровно сутки назад, `price24h_pcnt` — относительное
изменение, `prev_price1h` — часовой лаг для фьючерсов.

Синтетические поля: `bid1_price`, `ask1_price`, `bid1_size`, `ask1_size`, а для
linear также `mark_price`, `index_price`. Цены и размеры хранятся в Float64.
Ширина спреда округляется до целого числа тиков, затем центр согласуется с этой
шириной и ценовой сеткой. Это сохраняет положительный спред минимум один тик
без систематического удвоения узких спредов;
mark/index сохраняются как непрерывные оценки. Last не обязан находиться между
bid и ask. В объединённой таблице фьючерсные поля для спота пустые.
`usd_index_price`, funding, OI и остальные поля исходных тикеров не выводятся.

Требуется 1440 предыдущих закрытий плюс текущая свеча. Пропущенная или невалидная
свеча нарушает контекст; нулевой объём допустим. Для обучения неполные метки
исключаются, затем берётся общая сетка всех инструментов. Для генерации отсутствие
контекста в запрошенном диапазоне — ошибка. При ошибке потокового сохранения
манифест получает `status=failed`; уже записанные порции не считаются полным запуском.

По умолчанию обучающая метка — ближайший снимок в пределах ±5 секунд, при равенстве
выбирается более ранний. Это приближённое состояние на закрытии. Признаки никогда
не используют свечи, закрывающиеся после целевого времени. `prepare` сохраняет
смещение меток и расхождения last/close; загружает свечи только для общего периода
наличия меток с необходимой предысторией.

## Обучение и интерпретация качества

Модели обучают смещение mid, логарифм относительного спреда и нормированных
размеров, отклонения mark/index. Признаки описывают доходности, диапазон OHLC,
волатильность, относительные объёмы, шаг цены и спот-фьючерсный базис.
CatBoost предсказывает квантили 5/50/95%; масштаб равен ширине интервала с
нижним порогом. Пересекающиеся квантили упорядочиваются и учитываются в диагностике.

Разбиение общее для всех символов, без перемешивания:

- при истории короче 28 дней — 50/20/15/15% для train/validation/calibration/test;
- от 28 дней — последние три недели под validation/calibration/test, остальное train;
- минимум 480 общих минут для предварительного эксперимента.

Модель использует validation для early stopping. Для подбора блока первая половина
validation служит временным банком, вторая — контролем. Длины 1/5/15/60 сравниваются
по среднему из IQR-нормированных ошибок квантилей, ACF и корреляций; при равенстве
выбирается меньшая длина. Окончательный банк строится только на calibration.
Финальный test не участвует в подборе и не входит в банк.

Общий блок переносит остатки всех полей и инструментов вместе. Блоки выбираются
по похожести волатильности, объёма и базиса среди 20 ближайших допустимых начал;
блок не пересекает пропуски. В каждый момент используются текущие прогнозы центра
и масштаба. На test сравниваются медианный прогноз, независимые остатки и общий
блочный генератор. Проверяются хвосты, ACF, межрядовые корреляции, длительность
широкого спреда, скачки на стыках и покрытие интервалов.

На двух сутках тикеров результат **предварительный**. Нормализация цены помогает
генерации на старых свечах, но не подтверждает переносимость ликвидности на прошлые
годы. Диагностика выхода признаков за обучающий диапазон и использования текущих
шагов сохраняется в манифесте. После накопления истории нужно повторить проверку
на отложенных неделях. Статистическое сходство само по себе не подтверждает
доходность стратегии; минутные снимки также не описывают исполнение внутри минуты.

## Проверки

```bash
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
```

Тестовый набор содержит два символа на двух рынках с общим устойчивым фактором
ликвидности. Проверяются зависимости, причинность свечных признаков, границы окон,
сопоставление меток, пропуски, исторические правила, воспроизводимость, разбиение
на порции, поднаборы символов, запись Parquet, отчёты и защита от смешения выборок.
Тесты не требуют сети или доступа к ClickHouse.

Полные REST-состояния не требуют WebSocket delta. Если сборщик будет расширен,
для фьючерсов используется `wss://stream.bybit.com/v5/public/linear`, тема
`tickers.<symbol>`: после snapshot изменения delta применяются к сохранённому
состоянию. Отсутствующее поле означает отсутствие изменения. Спотовые тикеры
передаются снимками. См. [Bybit ticker stream](https://bybit-exchange.github.io/docs/v5/websocket/public/ticker).
