> Есть свечи и тикеры по споту и фьючерсам за некоторый промежуток времени. Нужно научиться восстанавливать тикеры по свечам для спота и фьючерсов для любого времени, на котором есть свечи.

**Я бы начал с обычного обучения с учителем: окно свечей → недостающие параметры тикера.** Практический первый вариант — CatBoost, нормализованные целевые значения и восстановление цен из них.

Для начала возьмём **один тикер на закрытие каждой свечи**. Это позволяет применять модель к любому участку свечной истории. Более частый поток внутри свечи потребует дополнительной модели.

Что именно восстанавливаем:

| Поле | Способ |
|---|---|
| `lastPrice` | Close торговой свечи на момент её завершения |
| `high/low/volume24h` | Скользящие агрегаты свечей при согласованных границах окна |
| `turnover24h` | Сумма turnover, если он есть в свечах; из одного OHLCV точно не получается |
| `bid/ask` | Обучаемая модель положения середины котировок и спреда |
| Размеры bid/ask | Отдельные обучаемые модели |
| `markPrice`, `indexPrice` фьючерса | Модели отклонения от наблюдаемых цен фьючерса и спота |
| `fundingRate`, `openInterest` | Отдельные статистические оценки; из свечей однозначно не определяются |

Такое разделение соответствует различию полей свечей и тикеров в API: свечи содержат торговые OHLC и объёмы, тикеры дополнительно содержат котировки и параметры деривативов. [Bybit API Documentation](https://bybit-exchange.github.io/docs/v5/market/tickers?utm_source=chatgpt.com)

**Ключевой приём — обучать отклонения и отношения, а не абсолютные цены.**

Например, для bid/ask:

\[
m_t=\frac{bid_t+ask_t}{2},\qquad
d_t=\frac{m_t-C_t}{C_t},\qquad
s_t=\frac{ask_t-bid_t}{C_t}.
\]

Модель предсказывает \(d_t\) и \(\log s_t\). Затем:

\[
\widehat m_t=C_t(1+\widehat d_t),\qquad
\widehat w_t=C_t\exp(\widehat{\log s_t}),
\]

\[
\widehat{bid}_t=\widehat m_t-\widehat w_t/2,\qquad
\widehat{ask}_t=\widehat m_t+\widehat w_t/2.
\]

После этого цены приводятся к шагу цены инструмента с сохранением положительного спреда. Так модель сможет работать и при существенно другом уровне цены.

Аналогично обучаются:

- отклонение `markPrice` от close фьючерса;
- отклонение `indexPrice` от close соответствующего спота — локальный спот не равен биржевому индексу;
- размеры котировок относительно типичного торгового объёма, с согласованными единицами.

Сам процесс я бы сделал таким:

1. **Собрать обучающие пары.** На каждое закрытие свечи — признаки свечей и актуальное состояние тикера на этот момент. Использовать последнее наблюдение не позднее границы; слишком старые снимки исключать. Если записан WebSocket Bybit, сначала собрать полное состояние из `snapshot/delta`: отсутствующее поле в delta означает отсутствие изменения. [Bybit API Documentation](https://bybit-exchange.github.io/docs/v5/websocket/public/ticker?utm_source=chatgpt.com)

2. **Посчитать небольшой набор признаков.** Доходности за несколько горизонтов, относительный диапазон и тело свечи, положение close внутри диапазона, волатильность, объём относительно скользящего среднего. Добавить синхронные признаки спота и фьючерса, их ценовой базис, относительный шаг цены и тип контракта. Для срочного фьючерса — время до экспирации. Во входах должны быть только данные, доступные и на восстанавливаемом участке.

3. **Обучить отдельную модель на каждую целевую величину.** Начать с медианной оценки; затем добавить, например, квантили 10/50/90%, чтобы получать диапазон возможных значений. CatBoost поддерживает `Quantile` и `MultiQuantile`. [CatBoost](https://catboost.ai/docs/en/concepts/loss-functions-regression?utm_source=chatgpt.com)

4. **Проверить на целиком отложенных неделях.** Скрыть тикеры, восстановить их по свечам и сравнить с настоящими. Оценивать ошибки спреда, смещения mid и mark в тиках или базисных пунктах. Большой \(R^2\) по абсолютной цене мало показателен: почти всё движение цены уже известно из close.

5. **Для реалистичной истории добавить совместные остатки.** Чистая регрессия выдаёт сглаженный, типичный тикер. Если нужна изменчивость настоящего рынка, к прогнозам добавляются блоки ошибок, взятые из похожих обучающих периодов. Остатки спота, фьючерса, спредов и размеров лучше выбирать совместно, чтобы сохранять зависимости.

**Главное ограничение «для любого времени» — переносимость между рыночными режимами.** Нормализация помогает переносить модель между уровнями цены, но не восстанавливает неизвестные изменения ликвидности, funding или OI. Поэтому качество надо проверять отдельно на спокойных и резких движениях; особенно осторожно интерпретировать абсолютный OI.

Если нужны тикеры каждую секунду из минутных свечей, эта схема остаётся основой, но дополнительно требуется генерировать внутриминутную траекторию. Само обучение на множестве секундных тикеров с одинаковыми признаками минутной свечи порядок событий не восстановит.

> Да, хорошо бы, чтобы получалась не сглаженная усреднённая детерминированная история, а были случайные колебания с реалистичным распределением.

**Да. Для первой версии я бы использовал CatBoost + условный блочный bootstrap остатков.** Это даст разные истории при одинаковых свечах, с колебаниями, похожими на наблюдавшиеся в настоящих тикерах.

Здесь нужно воспроизводить одновременно три свойства:

- **Распределение:** асимметрию, редкие большие отклонения, частые маленькие изменения.
- **Зависимость во времени:** широкий спред или низкая ликвидность могут держаться несколько последовательных шагов.
- **Связь между полями:** например, одновременное расширение спредов спота и фьючерса и уменьшение доступных объёмов.

Модель можно представить так:

\[
\widetilde{\mathbf y}_t
=
\boldsymbol{\mu}(\mathbf x_t)
+
\mathbf s(\mathbf x_t)\odot\mathbf r_t^*.
\]

Здесь:

- \(\mathbf x_t\) — признаки доступных свечей;
- \(\mathbf y_t\) — вектор нормализованных параметров тикеров: смещения mid, спреды, размеры котировок, отклонение mark;
- \(\mu(x)\) — типичные значения;
- \(s(x)\) — характерный масштаб колебаний в текущих условиях;
- \(r_t^*\) — случайно выбранные **совместные остатки из настоящей истории**.

Положительные величины, например спред, моделируем в логарифмах и затем преобразуем обратно.

Практически это работает следующим образом.

1. **Обучаем типичное значение и масштаб разброса.**  
   Например, CatBoost предсказывает медиану и несколько квантилей. Разность квантилей служит оценкой масштаба с нижним порогом, чтобы избежать деления на ноль. В CatBoost для этого есть `MultiQuantile`. [CatBoost](https://catboost.ai/docs/en/concepts/loss-functions-regression?utm_source=chatgpt.com)

2. **Собираем банк нормализованных остатков.**  
   На отдельном калибровочном участке вычисляем:
   \[
   \mathbf r_t=
   \frac{\mathbf y_t-\boldsymbol{\mu}(\mathbf x_t)}
        {\mathbf s(\mathbf x_t)}.
   \]
   Модель не должна обучаться на этом участке: ошибки на собственных обучающих данных могут сильно занизить реальную неопределённость. Сохраняем последовательность векторов остатков вместе с признаками рыночных условий.

3. **При генерации выбираем похожие исторические условия.**  
   По волатильности, объёму, базису и другим свечным признакам находим несколько подходящих мест в банке. Случайно выбираем одно из них с большим весом у более похожих наблюдений.

4. **Переносим последовательный блок остатков.**  
   Берём сразу несколько последовательных векторов, причём все поля спота и фьючерса — из одного исторического блока. Для каждого нового момента масштабируем их текущим \(s(x_t)\) и добавляем к текущему \(\mu(x_t)\).

Идея выборки последовательных блоков применяется в блочном bootstrap для работы с зависимыми временными рядами. Подбор блоков по рыночным условиям здесь — предлагаемая адаптация к твоей задаче. [doi.org](https://doi.org/10.1080/01621459.1994.10476870?utm_source=chatgpt.com)

Например, из реального участка может переноситься последовательность: **спред расширился → объёмы уменьшились → несколько шагов сохранялась плохая ликвидность → котировки восстановились**. Уровни цен при этом определяются твоими свечами, а амплитуда отклонений подстраивается под текущие условия.

**Длину блоков нужно подобрать на проверочных данных.** Слишком короткие блоки разрушают длительность эпизодов; слишком длинные плохо подстраиваются под смену режима. На стыках нужно отдельно проверять частоту искусственных скачков. Для медленных величин вроде OI и funding лучше сохранять состояние между шагами, используя ранее сгенерированное значение.

Качество проверяем на скрытом участке настоящих тикеров:

| Проверка | Что должно быть похоже |
|---|---|
| Квантили и хвосты | Частота обычных и больших отклонений |
| Автокорреляция | Длительность колебаний и эпизодов широкого спреда |
| Совместные движения | Связи между полями и рынками |
| Покрытие интервалов | Реальные значения попадают в заявленный 90%-й интервал примерно в 90% случаев |

**Известные величины остаются заданными свечами:** например, `lastPrice` на их закрытии. Случайность появляется в недостающих полях. При одинаковых свечах разные `seed` дают разные реализации; одинаковый `seed` позволяет воспроизвести конкретную историю.

Такой генератор воспроизводит наблюдавшиеся виды колебаний. События, аналогов которых нет в обучающих данных, придётся добавлять отдельными стресс-сценариями.
