# Как обучаются модели Reticker

Reticker обучается восстанавливать недостающие поля тикера по минутным торговым
свечам. Один обучающий пример — один инструмент на закрытии одной минуты:
признаки рассчитываются из свечей, а целевые значения — из настоящего снимка
тикера около этого закрытия. Инструмент здесь — пара `(category, symbol)`,
например `(spot, BTCUSDT)` или `(linear, BTCUSDT)`.

Генератор состоит из двух частей: CatBoost оценивает условные квантили полей,
а банк совместных остатков добавляет случайные колебания с наблюдавшимися
зависимостями между полями, инструментами и соседними минутами.

```text
kline + метаданные инструмента → свечные признаки ─┐
                                                   ├→ общая панель → временные части
spot_ticker / future_ticker → очистка и привязка ──┘

train       → модели CatBoost и параметры нормировки
validation  → ранняя остановка и подбор длины блока остатков
calibration → окончательный банк остатков
test        → итоговая проверка генератора
```

Ниже описана текущая реализация, без привязки к конкретному запуску. Точки входа —
[prepare](../src/reticker/dataset.py#L345),
[train](../src/reticker/model.py#L156),
[evaluate](../src/reticker/evaluation.py#L128); параметры и примеры вызовов приведены в
[README](../README.md).

## 1. Какие сырые данные используются

Символы и рынки задаются при подготовке данных. Поддерживаются символы USDT,
рынки `spot` и `linear` — линейные бессрочные фьючерсы USDT. Для каждого
выбранного символа необходимы данные каждого выбранного рынка. Фьючерсные
торговые свечи должны быть загружены отдельно от спотовых.

Через `ClickHouseSource` читаются следующие поля:

| Источник | Используемые поля | Назначение |
|---|---|---|
| [kline](../src/reticker/io.py#L161) | `time`, `category`, `symbol`, `interval`, `open`, `high`, `low`, `close`, `volume`, `turnover` | Признаки, опорные величины и вычисляемые поля результата; только `interval='1'` |
| [spot_ticker](../src/reticker/io.py#L174) | `time`, `symbol`, `bid1_price`, `ask1_price`, `bid1_size`, `ask1_size`, `last_price` | Метки для spot; `category='spot'` добавляется при чтении |
| [future_ticker](../src/reticker/io.py#L174) | Те же поля, а также `category`, `mark_price`, `index_price` | Метки для linear; фильтр `category='linear'` |

Тикер должен содержать полное состояние на момент `time`. Применение WebSocket
delta к предыдущему состоянию — задача внешнего сборщика. Reticker получает
готовые снимки. Остальные поля исходных тикеров в обучение не входят.

Ожидается, что `volume` и размеры лучших котировок выражены в согласованных
единицах количества базового актива, а `turnover` — в USDT. Нормировка размеров
ниже предполагает именно такую совместимость единиц.

Чтение выполняется из таблиц с `FINAL`, с настройкой ClickHouse `readonly=2`.
Время извлекается через Unix timestamp и приводится к UTC. Подключение берётся
из `CH_URL` в окружении или `.env`; окружение имеет приоритет. Для работы с уже
загруженными DataFrame есть `FrameSource` с теми же именами полей и колонкой
`category` для обоих рынков. См.
[ClickHouseSource](../src/reticker/io.py#L106) и
[FrameSource](../src/reticker/io.py#L82).

### Метаданные инструмента

Кроме свечей и тикеров нужны `tick_size` и `quantity_step`. По умолчанию
`prepare` получает текущие правила из публичного API Bybit и сохраняет их
в артефакте: `tickSize` для цены, `basePrecision` для количества на spot,
`qtyStep` для количества на linear. Загрузка реализована в
[MetadataCatalog.fetch](../src/reticker/metadata.py#L77).

Через `prepare --metadata` можно передать JSON с правилами для каждой пары
`market:symbol`, включая исторические интервалы `[valid_from, valid_to)`.
Датированное правило имеет приоритет над правилом без дат — fallback.
Пересекающиеся исторические интервалы запрещены. Если fallback отсутствует,
он догружается из Bybit; полный набор fallback позволяет работать без API.
Правила должны покрывать вычисляемую сетку, включая предысторию признаков.

`tick_size` участвует в признаке относительного шага цены и округлении результата;
`quantity_step` используется при восстановлении размеров котировок. Сам шаг
количества во входы CatBoost не включён. Признак `current_metadata` отмечает
использование правил с источником `bybit_current` для диагностики, но также
не подаётся модели. Текущие правила не являются подтверждённой исторической
спецификацией. Выбор правил по времени реализован в
[MetadataCatalog.values](../src/reticker/metadata.py#L53).

## 2. Как из исходных строк получается обучающая панель

Подготовкой управляет [prepare](../src/reticker/dataset.py#L345),
свечные признаки рассчитывает [candle_features](../src/reticker/dataset.py#L52).
Все границы ниже заданы в UTC; начало включено, конец исключён. Границы
запрошенного периода должны совпадать с границами минут. Незакрытые свечи
включать нельзя.

### Время закрытия и необходимая предыстория

В исходной свече `time` — начало минуты. В обучающей панели `time=t` — закрытие
свечи, начавшейся в `t−1 мин`. Обозначим её значения как `O_t`, `H_t`, `L_t`,
`C_t`, `V_t`, `T_t`: open, high, low, close, volume, turnover. Индекс `t−h`
далее означает сдвиг на `h` минут по времени закрытия. Переход к времени
закрытия выполняется [при построении индекса](../src/reticker/dataset.py#L92).

Для строки в `t` нужны **1441 последовательная валидная свеча**, с исходными
временами начала от `t−1441 мин` до `t−1 мин` включительно. Текущая свеча
даёт `C_t`, а самая ранняя — `C_(t−1440)` для суточной доходности. Суточные
агрегаты используют последние 1440 свечей; дополнительная свеча нужна для лага.

Сначала [prepare](../src/reticker/dataset.py#L349) читает тикеры за запрошенный период с запасом допуска
с обеих сторон. По первому и последнему времени сырых тикеров каждого потока
сокращает период до общего пересечения, с учётом допуска и минутных границ.
Если хотя бы один поток отсутствует или пересечения нет, подготовка завершается
ошибкой. Затем загружаются свечи от эффективного начала минус 1441 минута
до эффективного конца. Поэтому многолетняя свечная история при двух днях тикеров
не превращается в многолетнюю обучающую выборку.

Окончательные доступные минуты определяются после очистки и сопоставления меток;
они могут занимать более короткий период и иметь пропуски внутри него.

### Очистка свечей и контекст

После отбора минутного интервала дубликаты свечей определяются по
`(category, symbol, time)`, тикеров — по тому же ключу. Полностью одинаковые
повторные строки удаляются; различающиеся строки с одним ключом вызывают ошибку.
За это отвечает [deduplicate](../src/reticker/dataset.py#L37).

Свеча считается валидной, если выполнены
[проверки в candle_features](../src/reticker/dataset.py#L71):

- OHLC, `volume`, `turnover` конечны; все четыре цены положительны;
- `low <= min(open, close)` и `high >= max(open, close)`;
- `volume >= 0`, `turnover >= 0`, время начала находится на границе минуты.

Нулевой объём допустим. Невалидная свеча удаляется. Затем каждый поток
разворачивается на полную минутную сетку. Пропущенные свечи не заполняются
и не заменяются соседними: пропуск делает контекст невалидным до накопления
1441 последовательной валидной свечи. Так скользящее окно не может незаметно
перепрыгнуть через разрыв времени. См.
[построение минутной сетки](../src/reticker/dataset.py#L88) и
[проверку непрерывности](../src/reticker/dataset.py#L128).

При двух рынках для строки также нужен валидный контекст второго рынка того же
символа на том же закрытии. Все используемые признаки `f_*` должны быть конечны.
Свечи, закрывающиеся позже `t`, в строке `t` не используются. Проверки
[контекста второго рынка](../src/reticker/dataset.py#L176) и
[конечности признаков](../src/reticker/dataset.py#L177) завершают расчёт контекста.

### Очистка тикеров и выбор метки

До поиска ближайшего снимка удаляются невалидные тикеры. `bid1_price`,
`ask1_price`, `bid1_size`, `ask1_size`, `last_price` должны быть конечны
и строго положительны, а `ask1_price > bid1_price`. Для linear дополнительно
требуются конечные положительные `mark_price` и `index_price`. См.
[проверки в align_labels](../src/reticker/dataset.py#L220).

Для каждой строки с валидным свечным контекстом выбирается ближайший валидный
снимок того же инструмента по абсолютной разнице времени. По умолчанию
допустимо `|observed_time − t| <= 5 с`; при равном расстоянии выбирается более
ранний снимок. Допуск задаётся через `--tolerance-seconds`, разрешены целые
значения от 0 до 29. Без подходящего снимка строка исключается. Сопоставление
выполняется [через merge_asof](../src/reticker/dataset.py#L247), а смещение
[сохраняется отдельно](../src/reticker/dataset.py#L256).

Например, свеча с исходным `time=11:59:00` закрывается в `12:00:00`.
Снимок `12:00:02` может быть её меткой с `label_offset_seconds=+2`.
Если есть также снимок `11:59:58`, выбирается он, со смещением `−2`.
Снимок `12:00:06` при допуске 5 секунд не подходит. Везде подразумевается UTC.

Метка может находиться **после закрытия свечи**, поэтому это приближённое
состояние около границы минуты. При этом признаки по-прежнему содержат только
свечи, закрывшиеся к `t`. Разница между временем метки и границей сохраняется
для диагностики.

### Общая сетка инструментов

После сопоставления остаются только те минуты, для которых получена строка
**каждой** выбранной пары `(category, symbol)`. Пропуск метки одного инструмента
исключает минуту из общей панели всех инструментов. Это необходимо для общего
вектора остатков на одном историческом времени. См.
[фильтр общих минут](../src/reticker/dataset.py#L261).

Если выбрано `S` символов, `M` рынков и осталось `N` общих минут, в панели
будет `N × S × M` строк. Например, два символа на двух рынках дают четыре
строки на минуту. Панель сортируется по `time`, `category`, `symbol`.

## 3. Что именно подаётся на вход CatBoost

Вход каждой модели — **категориальный `symbol` и все числовые столбцы `f_*`**,
перечисленные в манифесте подготовленной выборки. При одном выбранном рынке
числовых признаков 14, при двух — 21. Модель получает агрегаты свечного окна
одной строкой; последовательность сырых свечей отдельным входом не передаётся.
Список `f_*` формируется [в candle_features](../src/reticker/dataset.py#L177),
а матрица входов с `symbol` — [в train](../src/reticker/model.py#L192).

В таблице `mean_60` — среднее по текущей и 59 предыдущим свечам;
$r_t = C_t / C_(t−1) − 1$; $ln$ — натуральный логарифм.

| Признак                                                                   | Формула / окно                                                                          | Код |
|---------------------------------------------------------------------------|-----------------------------------------------------------------------------------------|---|
| `f_return_1`, `f_return_5`, `f_return_15`, `f_return_60`, `f_return_1440` | $C_t / C_(t−h) − 1$, где $h$ — суффикс в минутах; простая относительная доходность      | [dataset.py:114](../src/reticker/dataset.py#L114) |
| `f_vol_5`, `f_vol_15`, `f_vol_60`                                         | Выборочное стандартное отклонение $r$ за последние $h$ минут, включая текущую; `ddof=1` | [dataset.py:117](../src/reticker/dataset.py#L117) |
| `f_range`                                                                 | $(H_t − L_t) / C_t$                                                                     | [dataset.py:118](../src/reticker/dataset.py#L118) |
| `f_body`                                                                  | $(C_t − O_t) / C_t$                                                                     | [dataset.py:119](../src/reticker/dataset.py#L119) |
| `f_close_position`                                                        | $(C_t − L_t) / (H_t − L_t)$; при нулевом диапазоне — $0.5$                              | [dataset.py:121](../src/reticker/dataset.py#L121) |
| `f_log_volume_ratio`                                                      | $ln(1 + V_t / max(mean_60(V), 1e−12))$                                                  | [dataset.py:124](../src/reticker/dataset.py#L124) |
| `f_log_turnover_ratio`                                                    | $ln(1 + T_t / max(mean_60(T), 1e−12))$                                                  | [dataset.py:124](../src/reticker/dataset.py#L124) |
| `f_relative_tick`                                                         | $tick\_size_t / C_t$                                                                    | [dataset.py:127](../src/reticker/dataset.py#L127) |

Если выбраны оба рынка, добавляются признаки второго рынка **того же символа**
на том же закрытии:

| Признак | Содержимое | Код |
|---|---|---|
| `f_peer_return_1`, `f_peer_return_5`, `f_peer_return_60` | Соответствующие доходности другого рынка | [dataset.py:114](../src/reticker/dataset.py#L114) |
| `f_peer_vol_60` | Волатильность другого рынка за 60 минут | [dataset.py:117](../src/reticker/dataset.py#L117) |
| `f_peer_range` | Относительный диапазон свечи другого рынка | [dataset.py:118](../src/reticker/dataset.py#L118) |
| `f_peer_log_volume_ratio` | Относительный объём другого рынка | [dataset.py:124](../src/reticker/dataset.py#L124) |
| `f_basis` | `C_t_linear / C_t_spot − 1`; одинаковая формула для строк обоих рынков | [dataset.py:170](../src/reticker/dataset.py#L170) |

Признаки второго рынка сначала рассчитываются по тем же формулам. Их
[выбор](../src/reticker/dataset.py#L147),
[переименование в f_peer_*](../src/reticker/dataset.py#L159) и
[присоединение к строкам текущего рынка](../src/reticker/dataset.py#L166)
выполняются далее в той же функции.

Свечные признаки других символов в строку не добавляются. Зависимости между
символами при генерации передаются через совместный банк остатков.

Абсолютные OHLC, время, `category`, исходные котировки, `size_reference`,
`quantity_step`, диагностические столбцы и целевые `y_*` непосредственно
в матрицу входов не входят. `category` определяет выбор модели. Дополнительная
стандартизация входов перед CatBoost не выполняется; нормировка контекста банка
остатков описана отдельно ниже.

## 4. Какие целевые значения обучаются

Вычислим по сопоставленному настоящему тикеру:

```text
B_t = bid1_price                         A_t = ask1_price
Qb_t = bid1_size                         Qa_t = ask1_size
mid_t = (B_t + A_t) / 2
size_reference_t = max(mean_60(V), 1e−12)
```

`size_reference` рассчитывается [из свечных объёмов](../src/reticker/dataset.py#L110).
Каждый целевой столбец панели имеет префикс `y_`; формулы реализованы в
[targets](../src/reticker/dataset.py#L182):

| Целевой столбец | Рынок | Формула | Код |
|---|---|---|---|
| `y_mid_offset` | spot, linear | `mid_t / C_t − 1` | [dataset.py:185](../src/reticker/dataset.py#L185) |
| `y_log_spread` | spot, linear | `ln((A_t − B_t) / C_t)` | [dataset.py:186](../src/reticker/dataset.py#L186) |
| `y_log_bid_size` | spot, linear | `ln(Qb_t / size_reference_t)` | [dataset.py:187](../src/reticker/dataset.py#L187) |
| `y_log_ask_size` | spot, linear | `ln(Qa_t / size_reference_t)` | [dataset.py:188](../src/reticker/dataset.py#L188) |
| `y_log_mark_ratio` | linear | `ln(mark_price_t / C_t_linear)` | [dataset.py:193](../src/reticker/dataset.py#L193) |
| `y_log_index_ratio` | linear | `ln(index_price_t / index_reference_t)` | [dataset.py:196](../src/reticker/dataset.py#L196) |

При двух рынках `index_reference_t = C_t_spot` того же символа. При обучении
только на linear `index_reference_t = C_t_linear`. Опорная цена нужна для
нормировки; спотовый close сам по себе не считается биржевым индексом. См.
[опорную цену по умолчанию](../src/reticker/dataset.py#L145) и
[замену на spot для linear](../src/reticker/dataset.py#L175).

Таким образом, модели обучают относительные смещения и логарифмы отношений.
Это позволяет восстанавливать абсолютные цены и размеры с учётом свечей
генерируемого периода. `size_reference` — средний **минутный** объём за час,
а не сумма объёмов за час и не объём стакана.

Исходный `last_price` тикера сохраняется как `observed_last_price` только
для контроля расхождения с close. Он не обязан совпадать с `C_t` и не заменяет
его в формулах целей. В диагностике сохраняются квантили ошибки
`(observed_last_price / C_t − 1) × 10000` в базисных пунктах.

### Поля, которые вычисляются из свечей

Эти поля не требуют обучения и при генерации определяются доступными свечами:

| Поле результата | Расчёт | Код |
|---|---|---|
| `last_price` | `C_t` | [dataset.py:97](../src/reticker/dataset.py#L97) |
| `prev_price24h` | `C_(t−1440)` | [dataset.py:98](../src/reticker/dataset.py#L98) |
| `price24h_pcnt` | `C_t / C_(t−1440) − 1` | [dataset.py:99](../src/reticker/dataset.py#L99) |
| `high_price24h`, `low_price24h` | Максимум high и минимум low по последним 1440 свечам | [dataset.py:101](../src/reticker/dataset.py#L101) |
| `volume24h`, `turnover24h` | Суммы по последним 1440 свечам | [dataset.py:101](../src/reticker/dataset.py#L101) |
| `prev_price1h` | `C_(t−60)`; в результате заполняется только для linear | [dataset.py:100](../src/reticker/dataset.py#L100), [generation.py:137](../src/reticker/generation.py#L137) |

Суточные окна содержат свечи с временами закрытия от `t−1439 мин` до `t`
включительно. Суточные агрегаты исходных тикеров не используются.
Funding, open interest, `usd_index_price` и внутриминутная траектория
в текущей версии не обучаются и не генерируются.

## 5. Как разделяются данные по времени

Разбиение выполняется после формирования общей панели. Один и тот же момент
времени относится к одной части для всех символов и рынков. Разбиение
хронологическое, без случайного перемешивания минут. Обе схемы и минимальные
размеры частей определены в [chronological_splits](../src/reticker/dataset.py#L283).

Пусть `N` — число сохранённых общих минут. Требуется хотя бы 480 минут.
От первого времени до последнего плюс одна минута определяется календарный
период панели; именно его длительность сравнивается с 28 днями.

| Часть | Период короче 28 дней: `preliminary` | Период от 28 дней: `weekly` | Использование |
|---|---|---|---|
| `train` | Первые примерно 50% минут | Всё до последних 21 суток | Обучение деревьев, пороги масштаба, нормировка контекста и диапазоны признаков |
| `validation` | Следующие примерно 20% | От 21 до 14 суток до конца | Early stopping и выбор длины блока |
| `calibration` | Следующие примерно 15% | От 14 до 7 суток до конца | Окончательный банк остатков |
| `test` | Последние примерно 15% | Последние 7 суток | Отложенная оценка |

Для короткой истории границы берутся по индексам `floor(0.5N)`, `floor(0.7N)`
и `floor(0.85N)` отсортированных уникальных минут. Поэтому проценты относятся
к числу сохранённых минут, а не к календарной длительности. Для недельного
режима границы календарные, и пропуски могут уменьшать число наблюдений.
В любом режиме дополнительно проверяется минимум 120 минут в `train`
и по 30 в каждой оставшейся части.

Между частями нет дополнительного временного зазора. Признаки начала следующей
части могут использовать более ранние свечи, включая свечи предыдущей части:
это доступная предыстория. Будущие свечи и поля тикеров во входы не добавляются.

## 6. Как обучается CatBoost

Обучение реализовано в [train](../src/reticker/model.py#L156). Для каждой пары
`(рынок, целевая величина)` создаётся отдельный `CatBoostRegressor`:
четыре модели для spot, шесть для linear, десять при двух рынках.

Каждая модель обучается сразу на **всех выбранных символах своего рынка**;
`symbol` передаётся как категориальный признак. Например, при `S` символах
и `N_train` общих обучающих минутах каждая модель рынка получает
`S × N_train` строк. Отдельных моделей на символ нет. Одна модель выдаёт
сразу три квантили своей целевой величины; отдельные модели на квантили
не создаются. Специальные веса строк не задаются.

| Параметр | Значение по умолчанию |
|---|---|
| Loss | `MultiQuantile:alpha=0.05,0.5,0.95` |
| Максимальное число итераций | `500` |
| Глубина деревьев | `6` |
| Learning rate | `0.05` |
| Random seed | `42` |
| Потоки CPU | `-1`, все доступные |
| Early stopping | `50` итераций без улучшения на validation |
| Устройство | CPU |

Итерации, глубину, learning rate, seed и число потоков можно менять через CLI
или [TrainingConfig](../src/reticker/config.py#L65). Три уровня квантилей и `early_stopping_rounds=50` заданы
в реализации. Деревья обучаются на `train`, весь `validation` передаётся
как `eval_set`; фактическое число деревьев может быть меньше заданного предела.
После настройки повторного обучения на объединении train и validation нет.
См. [создание CatBoostRegressor](../src/reticker/model.py#L195) и
[вызов fit](../src/reticker/model.py#L206).

### Центр и масштаб условного распределения

Для каждого входа три предсказанные квантили сортируются по значению,
если CatBoost выдал пересечение. Число таких случаев сохраняется в диагностике.
После упорядочивания:

```text
mu(x) = q50(x)
floor = max(1e−8, IQR(y_train) × 1e−3)
s(x) = max(q95(x) − q05(x), floor)
```

`IQR` — разность 75-го и 25-го процентилей. Порог вычисляется отдельно
для каждой модели по всем её обучающим целям, то есть по символам рынка вместе.
`s(x)` — ширина интервала, используемая как масштаб, а не оценка стандартного
отклонения. Проверка покрытия интервала выполняется отдельно на test. См.
[расчёт порога по train](../src/reticker/model.py#L218) и
[сортировку квантилей, центр и масштаб в predict](../src/reticker/model.py#L113).

## 7. Как строится и настраивается банк остатков

Банк строится в [make_bank](../src/reticker/model.py#L136) и содержит реальные
ошибки предсказания в нормированных координатах:

```text
r_t = (y_t − mu(x_t)) / s(x_t)
```

Для одной минуты сохраняется общий вектор всех целей всех инструментов
в фиксированном порядке. При `S` символах на двух рынках в нём `10 × S`
компонент. У каждого инструмента свои остатки; совместно выбирается их
историческое время, что сохраняет наблюдавшиеся межрядовые связи. Общий вектор
собирается функцией [panel_matrix](../src/reticker/statistics.py#L13).

### Контекст для поиска похожих условий

Вместе с остатками сохраняется вектор свечного контекста. Для каждого
инструмента в него входят `f_vol_60` и `f_log_volume_ratio`; при двух рынках
для linear добавляется `f_basis`. Контекст объединяется по всем инструментам.
Поэтому его размер при двух рынках — `5 × S`, при одном — `2 × S`.
Состав и порядок контекста заданы в
[context_matrix](../src/reticker/statistics.py#L31).

Каждая компонента контекста нормируется по **train**:

```text
z = (context − median(context_train)) / max(IQR(context_train), 1e−12)
```

Параметры нормировки вычисляются [в make_bank](../src/reticker/model.py#L146).

Для текущего контекста рассматриваются начала исторических блоков заданной
длины. Допустим только блок последовательных минут без разрывов. Расстояние —
корень из среднего квадрата разностей нормированных компонент контекста
текущей минуты и **первой минуты** блока. Берутся до 20 ближайших начал;
вероятности выбора пропорциональны `1 / (1 + distance)`.
Сходство всей будущей траектории блока не оценивается. См.
[ResidualBank.candidates](../src/reticker/model.py#L31) для проверки непрерывности
и [ResidualBank.neighbors](../src/reticker/model.py#L38) для поиска и весов.

### Выбор длины блока на validation

Подбор выполняется [в train](../src/reticker/model.py#L227):

1. Минуты validation делятся по порядку пополам: первые `floor(N_val / 2)`
   минут образуют временный банк остатков, остальные — контрольный участок.
2. Для длин `1`, `5`, `15`, `60` минут генерируются реализации на контрольном
   участке. Длины без непрерывного блока во временном банке пропускаются.
   Для каждой длины по умолчанию используются seed `0`, `1`, `2`.
3. После восстановления котировок и округления заново вычисляются целевые
   величины синтетических тикеров. Их распределение сравнивается с настоящими
   целями контрольного участка.
4. Выбирается длина с минимальным средним score по seed; при равенстве — меньшая.

Score — среднее трёх ошибок с одинаковыми весами:

- средняя абсолютная ошибка квантилей 1/5/50/95/99%, делённая для каждой
  компоненты на `max(IQR(real), 1e−8)`;
- средняя абсолютная разница автокорреляций на лагах 1/5/15/60 минут;
- средняя абсолютная разница внедиагональных межрядовых корреляций.

Меньший score лучше. Квантили в score характеризуют распределение получившейся
истории и отличаются от трёх условных квантилей, обучаемых CatBoost.
Расчёты определены в
[distribution_comparison](../src/reticker/statistics.py#L81),
[acf](../src/reticker/statistics.py#L59) и
[correlations](../src/reticker/statistics.py#L52).
Список длин настраивается через `--block-lengths`; `tuning_seeds` — через
Python `TrainingConfig`.

Весь validation уже использовался для early stopping. Его половины позволяют
разделить временный банк и контроль при выборе блока, но не являются полностью
независимой от настройки моделей оценкой. Для такой оценки отложен test.

### Окончательный банк

После выбора длины временный банк [заменяется банком](../src/reticker/model.py#L246),
рассчитанным **только на calibration**. Модели CatBoost на calibration не переобучаются; параметры
нормировки контекста остаются рассчитанными по train. Ни train, ни validation,
ни test в окончательный банк не добавляются.

Если в calibration нет непрерывного блока выбранной длины, обучение завершается
ошибкой. Автоматического сокращения длины или пополнения банка другими частями
выборки нет.

## 8. Как обученные величины превращаются в тикеры

При генерации для каждой текущей минуты из свечей вычисляются те же признаки,
затем новые `mu(x_t)` и `s(x_t)`. В начале блока выбирается похожий исторический
блок остатков. Его векторы последовательно переносятся целиком, совместно
для всех полей и выбранных инструментов:

```text
y_synthetic_t = mu(x_t) + s(x_t) × r_historic
```

На каждом шаге используются центр и масштаб **текущей** минуты, а не минуты
из банка. При длине 1 сохраняется совместный выбор полей, но последовательность
соседних остатков не переносится. При разрыве времени начинается новый блок.
Одинаковые входы, артефакт, набор символов и seed воспроизводят реализацию.
Выбор и перенос остатков реализованы в
[Simulation.run](../src/reticker/generation.py#L75), а добавление к прогнозам —
[в расчёте generated](../src/reticker/generation.py#L105).

До приведения к ограничениям обратные преобразования имеют вид:

| Поле | Восстановление |
|---|---|
| Mid и ширина спреда | `mid = C_t × (1 + y_mid_offset)`, `width = C_t × exp(y_log_spread)` |
| Bid/ask | `bid = mid − width/2`, `ask = mid + width/2` |
| Размеры | `bid1_size = size_reference_t × exp(y_log_bid_size)`, аналогично ask |
| Mark | `mark_price = C_t_linear × exp(y_log_mark_ratio)` |
| Index | `index_price = index_reference_t × exp(y_log_index_ratio)` |

При экспоненцировании значения ограничиваются диапазоном `[−50, 50]`.
Mid ограничивается снизу `1.5 × tick_size`, ширина — снизу одним тиком
и сверху `2 × (mid − tick_size)`. Затем ширина округляется до ближайшего
целого числа тиков, не меньше одного; bid округляется с учётом этой ширины,
а ask получается прибавлением целого числа тиков ширины к bid. Это обеспечивает
положительные цены и спред минимум один тик. Размеры округляются через
`np.rint` до шага количества с минимумом в один шаг. Mark и index сохраняются
как непрерывные цены. Last берётся из свечи и не обязан лежать между bid и ask.
Корректировки и пересечения квантилей учитываются в диагностике.
См. [reconstruct](../src/reticker/generation.py#L16), в частности
[округление цен](../src/reticker/generation.py#L36) и
[округление размеров](../src/reticker/generation.py#L41).

## 9. Что проверяется на test

Команда `evaluate` использует только отложенный test для сравнения трёх методов:

| Метод | Источник случайности |
|---|---|
| `median` | Медианы CatBoost без остатков, затем восстановление и округление |
| `independent` | Похожие остатки выбираются отдельно для каждой компоненты и минуты |
| `joint` | Общие последовательные блоки остатков из calibration |

По умолчанию случайные методы проверяются на 20 seed, `0…19`; median считается
один раз. Помимо описанного score отчёт содержит ошибки mid, спреда, mark/index
в тиках и базисных пунктах для медианного прогноза, хвосты распределений,
автокорреляции, межрядовые корреляции, длительности эпизодов широкого спреда
и скачки на стыках блоков. Отдельно измеряется покрытие интервала q05–q95
CatBoost и интервала между 5-м и 95-м процентилями ансамбля реализаций.

Перед оценкой проверяется соответствие хеша панели, набора инструментов
и разбиений модели и датасета, а также принадлежность времён банка calibration.
Test не используется для выбора длины блока или формирования банка.
Результаты сохраняются в `report.json`, `report.md`, `diagnostics.png`.
См. [evaluate](../src/reticker/evaluation.py#L128) и
[расчёт покрытия интервалов](../src/reticker/evaluation.py#L186).

## 10. Какие артефакты фиксируют обучение

| Этап | Файлы | Что в них зафиксировано |
|---|---|---|
| `prepare` | `panel.parquet`, `manifest.json` | Общая панель с признаками, исходными сопоставленными котировками, целями и диагностикой; выбранные инструменты, конфигурация и эффективный период, границы частей, список признаков, метаданные, качество данных и SHA-256 панели |
| `train` | `<market>_<target>.cbm`, `residuals.npz`, `manifest.json` | CatBoost для каждой цели рынка; времена, совместные остатки, контексты и их нормировка; параметры обучения, версии библиотек, хеш исходной панели, разбиения, метаданные, пороги масштаба, диапазоны признаков train, выбранная длина и её подбор, контрольные суммы и `model_id` |

`prepare` сохраняет число удалённых дубликатов и невалидных строк, наличие
контекста по потокам, число совпадений до общего фильтра и после него,
квантили смещения времени меток и расхождения last/close. Эти данные позволяют
увидеть, какие исходные наблюдения действительно дошли до обучения.

Каталоги вывода должны отсутствовать или быть пустыми. Обучение сначала
записывает манифест со статусом `training`, а после успешного сохранения всех
частей — `complete`. Загрузка сохранённого датасета и модели проверяет статус,
формат и контрольные суммы. `train` и `evaluate` работают с подготовленными
артефактами и не требуют повторного чтения ClickHouse или API Bybit.

Генерация поддерживает обученный поднабор символов и тот же набор рынков,
который зафиксирован в модели. Новый символ или другой набор рынков требует
подготовки данных и обучения отдельного артефакта.

Нормировка цен и размеров помогает применять модель к другому уровню рынка,
но не подтверждает переносимость ликвидности на прошлые годы. При периоде
короче 28 дней оценка помечается `preliminary`; после накопления истории
её следует повторить на отложенных неделях. При генерации диагностируется
выход признаков за диапазоны train и использование текущих правил инструмента.
Минутные снимки описывают состояние около закрытия, но не исполнение ордеров
внутри минуты и не события, аналогов которых не было в исходных данных.
